# Изолированный сетевой пилот WorkControl

## Статус допуска

Код режима `Pilot` подготовлен, но реальное двухкомпьютерное испытание в текущей среде не выполнено. До отдельного технического допуска разрешены только LOCAL и синтетические данные. Реальные данные сотрудников запрещены.

## Обязательные условия

- согласованное DNS-имя, например `workcontrol-pilot.example.local`;
- серверный PFX/P12 с SAN для этого DNS-имени и доверенной цепочкой на обоих тестовых ПК;
- отдельный тестовый сегмент и ровно два согласованных устройства;
- постоянный каталог Data Protection вне репозитория с ограниченными ACL;
- резервная копия БД и назначенный ответственный за остановку;
- подтверждение входа, ролей, одноразового enrollment, отзыва и аудита на синтетических данных.

## Подготовка пакета

Из PowerShell в корне репозитория:

```powershell
.\scripts\prepare-pilot.ps1 `
  -PilotHost workcontrol-pilot.example.local `
  -CertificatePath C:\Secure\workcontrol-pilot.pfx `
  -DataProtectionKeyPath C:\ProgramData\WorkControl\keys
```

Сценарий собирает web/API/agent в `release\pilot`, но не копирует сертификат, не спрашивает его пароль и не меняет брандмауэр.

## DNS, TLS и брандмауэр

1. ИТ-администратор создаёт DNS-запись только в тестовой зоне.
2. Сертификат устанавливается/хранится в защищённом каталоге сервера; корневой сертификат доверен на тестовом клиенте.
3. После отдельного разрешения ИТ-администратор создаёт входящее правило только для TCP 5443, профиля Domain/Private, серверной программы и адресов тестового сегмента. Запрещены `Any` для удалённых адресов и Public profile.
4. Репозиторий намеренно не содержит автоматической команды изменения firewall.
5. Проверка `http://...` должна завершаться без передачи данных; рабочий адрес — только `https://DNS:5443`.

## Запуск

```powershell
.\scripts\start-pilot.ps1 `
  -PilotHost workcontrol-pilot.example.local `
  -CertificatePath C:\Secure\workcontrol-pilot.pfx `
  -DataProtectionKeyPath C:\ProgramData\WorkControl\keys
```

Пароль PFX читается как SecureString и не сохраняется. API и собранная React-панель обслуживаются одним HTTPS origin. Валидатор блокирует PILOT при HTTP, IP вместо DNS, несовпадении URL и DNS, отсутствии PFX/P12 с паролем либо key ring внутри репозитория.

## Проверка двух ПК

1. Создать локального ADMIN и войти по HTTPS.
2. Создать одноразовый код; на втором ПК указать тот же HTTPS DNS-адрес.
3. Подтвердить, что недоверенный сертификат приводит к отказу и обход TLS отсутствует.
4. Одобрить Pending-устройство, отправить синтетическое событие, проверить БД и панель.
5. Отключить сеть на несколько минут, затем проверить доставку очереди.
6. Выполнить ротацию и отзыв; старый ключ и отозванный агент должны получить отказ.

В текущем отчёте эти пункты помечены «не проверено: нужен второй компьютер, DNS и сертификат».

## Остановка и откат

1. Остановить `start-pilot.ps1` сочетанием `Ctrl+C`.
2. ИТ-администратор отключает созданное точечное правило firewall и удаляет тестовую DNS-запись.
3. Отозвать тестовые устройства в панели.
4. Сохранить журналы без секретов и резервную копию БД; удалить пакет `release\pilot` как воспроизводимый артефакт.
5. При проблеме схемы остановить API и восстановить БД только из проверенной резервной копии. Не применять `EnsureDeleted`, `database drop` или ручное удаление таблиц.
