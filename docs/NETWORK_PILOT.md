# Подготовка сетевого пилота

## Текущий статус: заблокирован

`TASK-002` разрешает только испытание на одном компьютере через `127.0.0.1`. Сетевой пилот с реальными именами пользователей, компьютеров или рабочей телеметрией запрещён, потому что в прототипе ещё нет аутентификации агентов, авторизации пользователей и HTTPS.

`manager.bat` намеренно не создаёт правило брандмауэра и не привязывает API к сетевому интерфейсу. Агент `TASK-002` отклоняет адрес API, который не является loopback-адресом.

## Явная процедура допуска будущего пилота

Сетевой запуск можно готовить только после технической приёмки `TASK-003` и отдельного разрешения владельца проекта:

1. Подтвердить аутентификацию каждого агента и возможность отзыва его ключа.
2. Подтвердить вход пользователей и разграничение ролей.
3. Настроить доверенный HTTPS-сертификат и запретить HTTP.
4. Зафиксировать тестовый сегмент сети, список устройств и ответственного.
5. Утвердить состав и срок хранения данных; использовать синтетические данные до отдельного разрешения на реальные.
6. Создать ограниченное правило брандмауэра только для утверждённого сегмента.
7. Провести проверку журнала доступа, удаления данных и остановки пилота.
8. Только после этого создать отдельный явный сценарий сетевого запуска.

До выполнения всех пунктов команды сетевой привязки и открытия порта в репозиторий не добавляются.
