# Первый локальный запуск WorkControl

Эта инструкция рассчитана на пользователя без навыков программирования. Локальный запуск доступен только на текущем компьютере и не открывает сетевой порт.

## 1. Установите зависимости

1. Установите .NET 10 SDK с сайта Microsoft.
2. Установите Node.js 20 LTS или новее.
3. Перезагрузите Windows, если установщик этого потребовал.

## 2. Создайте администратора

1. Дважды щёлкните `bootstrap-admin.bat`.
2. Введите новый сложный пароль. Символы пароля не показываются.
3. Дождитесь сообщения «Локальный администратор создан».

Процедура работает только один раз для пустой базы. Пароль передаётся API через переменную среды дочернего процесса, не записывается в файлы и очищается после завершения.

## 3. Запустите сервер и панель

1. Дважды щёлкните `manager.bat`.
2. Не закрывайте два открывшихся окна API и Web.
3. Браузер откроет `http://127.0.0.1:5173`.
4. Войдите: email `admin@workcontrol.local`, пароль — созданный на шаге 2.

Если окно сообщает об отсутствии .NET или Node.js, установите указанную зависимость и повторите запуск.

## 4. Подключите тестовый агент

1. В панели нажмите «Создать код».
2. Запустите `release\agent\employee.bat`.
3. Оставьте адрес `http://localhost:5080`, вставьте код и нажмите «Подключить этот компьютер».
4. В панели у заявки выберите тестового сотрудника и нажмите «Одобрить».
5. В агенте нажмите «Отправить контрольное событие», затем «Обновить» в панели.

Код действует 10 минут и применяется один раз. До одобрения события не принимаются. В чистом LOCAL создаётся только явно подписанный «Тестовый сотрудник (LOCAL)»; в PILOT демонстрационная запись не создаётся, сотрудников должен заранее подготовить администратор данных.

## 5. Что считать успешным

- панель требует вход;
- компьютер появляется только после одноразового кода и одобрения;
- статус «На связи» и активность показаны независимо;
- при остановленном API агент сообщает, что событие осталось локально;
- после запуска API очередь отправляется;
- повтор одного EventId не создаёт вторую запись.

## Остановка

Закройте окна `WorkControl API` и `WorkControl Web`, затем окно агента. Правила брандмауэра удалять не нужно: локальная процедура их не создаёт.

Не копируйте `agent-settings.json`, `agent-credential.bin` или каталог ключей Data Protection на другой компьютер. Для нового компьютера создайте новый одноразовый код.
