# Итог TASK-003

Дата локальной проверки: 25 ноября 2026 года.

## Статус

TASK-003A–003E реализованы в коде и прошли доступные локальные автоматические проверки. Режим `Local` остаётся изолированным на текущем компьютере. Код сетевого режима `Pilot` подготовлен с обязательными HTTPS, DNS, внешним key ring и PFX/P12, но реальный двухкомпьютерный пилот не проводился.

До отдельного технического допуска, согласованных DNS/сертификата/сегмента и выполнения ручного сценария из `docs/NETWORK_PILOT.md` запрещены реальные данные сотрудников и массовая установка.

## Что реализовано

- переход API, Windows-агента и тестов на .NET 10;
- EF migrations для чистой и существующей SQLite с сохранением устройств и событий;
- Identity с ролями `ADMIN`, `MAIN_USER`, `GROUP_MANAGER`, ограничением групп в SQL-запросе, cookie, lockout, CSRF и аудитом;
- одноразовый локальный bootstrap первого администратора без пароля в Git;
- одноразовое подключение агента, Pending/approval, отдельные 256-битные credentials, ротация и отзыв;
- хранение agent secret через Windows DPAPI и серверное хранение только SHA-256;
- защищённый endpoint событий, дедупликация, проверка времени/JSON/размера и офлайн-очередь;
- React-панель без демонстрационной подстановки при ошибке API;
- отдельные сценарии подготовки и запуска HTTPS PILOT без автоматического изменения DNS или firewall;
- документация первого запуска, разработки, метрик, безопасности агента и сетевого пилота.

## Действия пользователя для LOCAL

1. В чистой копии репозитория запустить `bootstrap-admin.bat` и задать новый пароль.
2. Запустить `manager.bat` и войти в панель на `http://127.0.0.1:5173`.
3. Создать одноразовый код подключения.
4. Запустить `release\agent\employee.bat`, указать локальный API и код.
5. В панели выбрать тестового сотрудника и одобрить Pending-устройство.
6. Отправить тестовое событие и убедиться, что компьютер отображается в сводке.

Подробная пошаговая инструкция находится в `docs/FIRST_RUN_CHECKLIST.md`.

## Не проверено и оставшиеся ограничения

- реальный PostgreSQL;
- реальный HTTPS/DNS/firewall на двух компьютерах и отказ на втором ПК при недоверенном сертификате;
- длительный пилот и нагрузка до 100 компьютеров;
- ручная проверка обновлённого защищённого интерфейса человеком после последнего усиления PILOT;
- интерфейс создания дополнительных пользователей и назначения групп;
- автоматическая плановая ротация credential в UI агента.

Эти пункты не считаются успешными. Они требуют отдельного задания, инфраструктуры и технического допуска.
