# WorkControl

WorkControl — ограниченный прототип технического учёта активности. Агент передаёт только состояние active/idle, исходное число секунд простоя и признак длительного отсутствия. Снимки экрана, сайты, нажатия клавиш, текст и содержимое документов не собираются. Техническая сводка не является утверждённым табелем и не оценивает качество работы сотрудника.

## Что реализовано

- ASP.NET Core API и SQLite/PostgreSQL-модель с EF migrations;
- защищённый вход в панель, роли `ADMIN`, `MAIN_USER`, `GROUP_MANAGER`, серверное ограничение групп;
- одноразовое подключение агента, одобрение устройства, отдельные ключи агента, ротация и отзыв;
- Windows-агент с DPAPI-хранилищем секрета и устойчивой SQLite-очередью;
- React-панель без подстановки демонстрационных строк при ошибке API;
- режим `Local`, привязанный к текущему компьютеру, и блокируемый валидатором режим `Pilot`;
- автоматические проверки API, агента и веб-интерфейса в GitHub Actions.

## Первый локальный запуск

Нужны Windows, .NET 10 SDK `10.0.404` (или новый патч ветки 10.0.4xx) и Node.js 20+. Репозиторий не зависит от `.tools/dotnet`.

1. В чистой копии репозитория один раз запустите `bootstrap-admin.bat`. Введите пароль; он не записывается в Git или настройки.
2. Запустите `manager.bat`. API будет слушать только `http://127.0.0.1:5080`, панель — `http://127.0.0.1:5173`.
3. Войдите как `admin@workcontrol.local` (или email, заданный параметром bootstrap-процедуры).
4. В блоке «Подключение агентов» создайте одноразовый код.
5. Запустите `release\agent\employee.bat`, введите код и дождитесь заявки `Pending`.
6. В панели выберите сотрудника и нажмите «Одобрить». Только после этого события принимаются API.

Подробная инструкция для пользователя: [docs/FIRST_RUN_CHECKLIST.md](docs/FIRST_RUN_CHECKLIST.md). Команды разработки: [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

## Безопасность

- Панель не имеет публичной регистрации; первый ADMIN создаётся однократной локальной CLI-процедурой.
- Cookie: HttpOnly, SameSite=Strict, ограниченный срок, lockout; изменяющие browser-запросы требуют CSRF-токен.
- Секрет агента выдаётся один раз, на сервере хранится только SHA-256, на Windows-клиенте — DPAPI CurrentUser.
- Анонимные legacy endpoints `/api/devices/register` и `/api/telemetry/events` удалены.
- В режиме `Pilot` приложение отказывается стартовать без явных HTTPS URL, DNS-имени и постоянного каталога Data Protection.
- `manager.bat` не повышает права, не меняет брандмауэр и не открывает сетевой интерфейс.

## Пороги активности

- неактивность: 60 секунд;
- длительное отсутствие: 300 секунд.

Их можно изменить переменными `WORKCONTROL_IDLE_THRESHOLD_SECONDS` и `WORKCONTROL_LONG_ABSENCE_THRESHOLD_SECONDS`. Исходное число секунд простоя сохраняется без подмены статуса потерей связи.

## Сетевой пилот

Репозиторий умеет подготовить same-origin пакет API+web и строго запустить его по HTTPS, но не создаёт DNS, сертификат или правило брандмауэра. Реальный сетевой пилот запрещён до отдельного допуска и успешного синтетического испытания на двух компьютерах. Процедуры подготовки, запуска, остановки и отката: [docs/NETWORK_PILOT.md](docs/NETWORK_PILOT.md).
