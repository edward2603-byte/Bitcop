# WorkControl

WorkControl — прототип локальной системы технического учёта активности. Текущий этап подтверждает базовую цепочку: Windows-агент регистрирует тестовое устройство, сохраняет события при отсутствии API, повторно отправляет очередь после восстановления связи, а локальная панель показывает полученные данные.

Агент передаёт только состояние активности, исходную длительность простоя и признак длительного отсутствия. Он не собирает нажатия клавиш, текст, снимки экрана, сайты и содержимое документов. Техническая сводка не является утверждённым табелем и не используется для автоматической оценки сотрудника.

## Состав

- `src/server/WorkControl.Api` — ASP.NET Core API, SQLite для локального испытания и модули Organization, Devices, Telemetry.
- `src/agent/WorkControl.Agent` — тестовый WPF-агент с локальной SQLite-очередью.
- `src/web` — React/Vite-панель с явно разделёнными API- и демонстрационными данными.
- `tests/WorkControl.Api.Tests` — проверки API, очереди агента и порогов активности.
- `.github/workflows/verify.yml` — автоматическая сборка и тестирование на Windows.

## Локальный запуск

Требуются поддерживаемая версия Windows 10/11, .NET 10 SDK `10.0.404` или более новый патч ветки `10.0.4xx` и Node.js 20 или новее. Версия SDK закреплена в `global.json`. Папка `.tools` не используется и не требуется.

1. Получите чистую копию репозитория.
2. Запустите `manager.bat` двойным щелчком.
3. Скрипт проверит зависимости, восстановит пакеты, создаст `release/agent` и запустит API и панель только на `127.0.0.1`.
4. Запустите `release/agent/employee.bat` на этом же компьютере и оставьте адрес `http://localhost:5080`.
5. Нажмите «Отправить контрольное событие» и обновите панель `http://127.0.0.1:5173`.

`manager.bat` не запрашивает права администратора, не создаёт правило брандмауэра и не открывает API для локальной сети. Тестовый агент также отклоняет нелокальные адреса API. Простая инструкция: [docs/FIRST_RUN_CHECKLIST.md](docs/FIRST_RUN_CHECKLIST.md).

## Параметры активности

Значения по умолчанию:

- неактивность — 60 секунд;
- длительное отсутствие — 300 секунд.

Для отдельного тестового запуска их можно изменить переменными среды `WORKCONTROL_IDLE_THRESHOLD_SECONDS` и `WORKCONTROL_LONG_ABSENCE_THRESHOLD_SECONDS`. Второй порог должен быть больше первого. Исходное число секунд простоя сохраняется в событии без округления до статуса.

## Ограничение сетевого пилота

Сетевой пилот с реальными данными запрещён до реализации аутентификации агентов, авторизации пользователей и HTTPS в отдельной задаче [docs/TASK-003.md](docs/TASK-003.md). Текущая процедура подготовки и блокирующие условия описаны в [docs/NETWORK_PILOT.md](docs/NETWORK_PILOT.md).

Команды разработки и проверки: [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).
